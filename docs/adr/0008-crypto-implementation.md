# 0008. Crypto implementation: Web Crypto plus hash-wasm, and the details SEC-1…3 leave open

- Status: Accepted
- Date: 2026-11-24

## Context

SRS 5.2 fixes the algorithms (Argon2id, HKDF-SHA256, AES-256-GCM, HMAC-SHA256) but not the library for Argon2id, which Web Crypto doesn't provide. It also leaves several details open that become part of every user's stored data once records exist. Earlier guidance asked for "one audited Argon2 WASM library". When this was written there was none:

| Library | Argon2id | Audited | Notes |
| ------- | -------- | ------- | ----- |
| `@noble/hashes` | Pure JS | The library is (Cure53, 2022), but its README states Argon2 was outside the audit's scope | Several times slower than WASM at 64 MiB |
| `hash-wasm` | WASM, inlined | No | Actively maintained; works unchanged in Node, Vite builds and MV3 extensions; no associated-data input |
| `argon2id` (openpgpjs) | WASM | No separate audit | Used by OpenPGP.js; supports associated data; each app has to load the `.wasm` files itself; last release 2023 |

## Decision

1. **Web Crypto** for HKDF, AES-GCM, HMAC, SHA-256 and randomness. It's available in Node and every target browser, and needs no dependency.
2. **`hash-wasm`** for Argon2id. It runs the same code everywhere without per-app loaders. Its correctness is checked by the reference implementation's Argon2id vectors (`packages/core/test/vectors/argon2id-reference.json`) in Node, Chromium and Firefox on every PR. Tazamun doesn't use Argon2's associated-data input, so the missing option costs nothing. The library sits behind one function (`argon2idRaw`), so replacing it touches one file.
3. Details that SEC-1…3 leave open, now fixed as **format v1**:
   - Passphrases are normalized to **Unicode NFC** before UTF-8 encoding, so the same passphrase typed on macOS and Windows derives the same keys.
   - **KDF parameters are never lowered.** Clients reject prelogin parameters below the SEC-1 defaults, or above sane ceilings (1 GiB, 10 passes, 4 lanes). A malicious server can't make the auth key cheaper to brute-force, or freeze clients.
   - The wrapped account key uses AAD `tazamun/v1/account-key|<accountId>`.
   - HKDF uses an **empty salt**. The input is the uniformly random account key, so a salt adds nothing (RFC 5869, section 3.1).
   - Keyed record IDs (history) are the **first 16 bytes** of the HMAC, base64url-encoded (22 characters).
   - `seal` draws its own random nonce. It is the only place in `packages/core` that uses randomness internally, so that no caller can reuse a nonce.
4. Tazamun's own constructions are pinned by **format vectors** (`tazamun-format-v1.json`). They were generated by this code and checked against an independent computation with `node:crypto`.

## Consequences

- No audited Argon2id is in use. This is a gap for SEC-10 (security review before 1.0) to cover. If an audited WASM Argon2id appears, switch to it once it passes the same vectors.
- Any change to the format v1 details breaks existing data. It needs a new format version, a migration, and a superseding ADR.
- The extension CSP must allow `'wasm-unsafe-eval'` (already planned), because `hash-wasm` compiles WASM at run time.
