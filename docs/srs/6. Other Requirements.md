## 6. Other Requirements

### 6.1 Licensing

- Tazamun is licensed under the MIT License (see [`LICENSE`](../../LICENSE)).
- Every dependency must have a license compatible with MIT distribution (MIT, BSD, Apache-2.0, ISC and similar). CI checks this. Copyleft dependencies need a discussion first.
- Contributions are accepted under the project license (inbound = outbound). No CLA.

### 6.2 Store Publishing

The server is distributed as a container image (GHCR, mirrored to Docker Hub), following section 3.11 and [ADR-0007](../adr/0007-container-distribution.md). The browser extension is distributed through the stores below.

| Store | Requirements to plan for |
| ----- | ------------------------ |
| Chrome Web Store | One-time developer registration fee. Privacy practices form and a justification for each permission (`history`, `tabs`, `management` and `bookmarks` will be reviewed carefully). A privacy policy URL. |
| Microsoft Edge Add-ons | Free. A similar review of permissions and privacy policy. |
| Firefox Add-ons (AMO) | Free. Because the code is bundled, **source code and build instructions must be uploaded** with each version so the build can be reproduced. A fixed add-on ID in `browser_specific_settings.gecko.id` (`tazamun@proless.github.io`). New add-ons must declare data collection for Firefox's built-in consent (Firefox 140+): sending data to the user's own server counts even though it is encrypted, so tabs and history are declared as `browsingActivity` (required), and bookmarks and the extension list as optional categories. |

- Releases are built in CI from a tagged commit. The store packages and the source archive come from the same build.
- Store descriptions must not use other browsers' trademarks beyond describing compatibility.

### 6.3 Internationalization

- English is the source language. All strings live in locale files (`_locales` for the extension manifest, plus a JSON catalog for UIs).
- The UI must support right-to-left languages from the start. Arabic is the first planned translation (*tazāmun*, تزامن, means "synchronization").
- Dates, times and numbers are formatted with the `Intl` APIs in the user's locale.

### 6.4 Data Retention and Legal

- People who self-host are the data controllers for their instances. The project provides a privacy-policy template for instance operators.
- Clients set expiry on tombstones (90 days), history (the retention setting) and send-tab commands (7 days). The server stops returning a record as soon as it expires and deletes expired records every hour.
- Deleting an account removes everything immediately (ACC-10). Backups follow the operator's own policy, which the operator documentation must point out.

### 6.5 Known Limitations and Open Questions

**Limitations accepted for 1.0:**

1. Losing both the passphrase and the recovery key, with no other signed-in device, means the data can't be recovered.
2. A malicious server can withhold records or replay old versions without detection (no signed history or transparency log in v1).
3. A malicious server can serve a backdoored dashboard. Users who don't trust the operator should use only the extension.
4. Rotating the account key after a compromise needs re-encrypting everything. This is not in 1.0; it's a manual procedure: export, delete account, create a new one, import.
5. Firefox bookmark tags and keywords, Chromium tab group colours, reading lists, and other data without extension APIs are not synced.
6. Sizes and timing of records are not padded, so traffic analysis can reveal activity patterns.
7. Desktop only. Firefox for Android is the first mobile target after 1.0.
8. One account per browser profile (ACC-12). Several accounts in one browser need one browser profile each; the extension doesn't switch between accounts.
